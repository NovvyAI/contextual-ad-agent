01 — 概述

怎么定的这份计划

这不是从零设计一套新工程——Toonflow-app 已经有一整套「Express + Socket.IO + SQLite + 统一模型供应商层」的骨架，且已经内置了 Seedance 2.0 的视频供应商适配；ads-gen-agent-main 已经跑通了「多模态分析 → 创意生成 → 视频渲染」这条链路要用的具体模型。这份计划的核心工作是把架构设计文档里的 Agent 按 Toonflow 的工程约定搭出来，模型选型直接照抄 ads-gen-agent 已验证的配置，而不是重新选型。

阅读前提：本仓库里 Toonflow 前端只有编译产物（data/web），没有源码。从产物特征（Vue 3 编译期 _ctx. 渲染函数签名、VITE_DEV 环境变量）判断其技术栈是 Vue 3 + TypeScript + Vite，前端相关任务按此假设排期，若实际前端仓库技术栈不同需要调整 M5。

06 — 关键技术决策

几个值得记录的选择

参考素材直接走 base64，不新增对象存储层
ads-gen-agent 用 GCS 给 Seedance 传参考素材 URL；Toonflow 现有供应商层已支持参考图/视频以 base64 直传（referenceList2imageBase642），可以跳过这一层，减少工作量。
Whisper 用本地 ONNX（transformers.js），不起 Python 子进程
前后端统一 TS 是硬性要求；Toonflow 已有 @huggingface/transformers 依赖跑本地 Embedding 模型，同一套运行时可以承载 Whisper，避免引入 Python 运行时依赖。
build_playable.py 移植为 TS，而不是保留 Python 子进程
该脚本本质是文件装配 + 模板注入 + ffmpeg 拼接，没有 Python 专有能力依赖，移植成本可控，符合全 TS 的要求。
