contextual-ad-agent · M0–M7

Agent 之间的数据流向图

三类通信渠道：data/skills/*.md 定义每个 Agent 的角色指令（不传数据）； SQLite 表是真正的 agent 间通信总线（写 JSON blob / 读 id 句柄）； 内存里的 TS interface 只在单次函数调用的参数/返回值里存在，用完即弃。

Skill 文件（markdown）

配置 Agent 人格/指令，运行时 fs.readFile 读入当 system prompt，不是被交换的数据本身

数据库（SQLite 表）

Agent 间真正的通信总线；大多只传一个 id 句柄，下游自己重新查库还原上下文

Agent / 编排代码

读写数据库、调用模型的执行单元；相互之间基本不直接调用，靠数据库中转

Socket 消息 / 前端

纯 TS discriminated union，序列化成 JSON 走 Socket.IO，不落库，即时消费即丢弃

写入 / 主流程调用
读取 / 引用（不改变状态）
