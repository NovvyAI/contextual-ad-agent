## 这个里程碑交付了什么

## 过程中的重要发现（不是假设，是实际读代码验证过的）

1. **Toonflow 其实没有能用的 Anthropic 供应商**——`data/vendor/*.ts` 里 `declare const createAnthropic` 只是个从没被真正调用过的占位声明，11 个供应商脚本没有一个用到它。`anthropic.ts` 是照着 `openai.ts` 的模板从零写的。
2. **Seedance 2.0 视频生成 Toonflow 本来就支持**——`atlascloud.ts`/`volcengine.ts`/`volcengineSd2.ts` 已经有相关适配，不用新写。
3. **`vendor2json`/`vendor.json` 这套机制对 web-only 部署没用**——它存在的意义是 Electron 打包后要把供应商脚本快照同步到用户数据目录；web-only 下 `getPath("vendor")` 本来就指向仓库自带的 `data/vendor`，这层间接完全是死代码，还是个"忘记跑就启动失败"的坑，直接删掉了（原计划里是打算照抄的，属于对计划的偏离）。

## 环境问题与处理

1. **Node.js 完全没装**——只有 PyCharm 内部自带的一份（不在 PATH 里）。`brew install node` 因为本机 Xcode（10.3）太老触发从源码编译，直接失败。改成直接下载官方预编译的 Node v24.18.0（LTS）二进制，软链进 `~/.local/bin`。
2. **yarn 不可用**——通过 `corepack enable` + `corepack prepare yarn@1.22.22 --activate` 解决。
3. **esbuild 打包报错**——`src/app.ts`/`env.ts`/`getPath.ts` 里的 Electron 分支虽然是死代码，但 `require("electron")` 这行语法本身需要 esbuild 打包时显式标记成 external 才能跳过；同时 knex 的 `mariadb` 方言驱动也需要标记 external，两个都加进了 `scripts/build.ts` 的 external 列表。

## M0 之后的补充（严格算是骨架层改动，不属于 M1 的 Agent 实现）

在 M0 宣布完成之后、M1 正式开始之前，又做了两处基础设施层面的调整：

1. **Seedance 供应商从 `atlascloud` 换成新写的 `imarouter.ts`**——用户希望和已有的 `ads-gen-agent-main`（Python 参考实现）用同一个视频生成平台（ImaRouter，`api.imarouter.com`），照着 `ads-gen-agent-main` 的 `tools/seedance.py` 接口契约新写了一份供应商适配，`atlascloud.ts` 保留没删。
2. **`.env` 自动同步机制**——为了不用每次改密钥都手写 curl，加了 `src/lib/syncEnvVendors.ts`（应用启动时读 `.env` 里的 `*_API_KEY`/`*_BASE_URL`，自动同步进 `o_vendorConfig` 并启用），`.env.example` 作为模板提交进仓库，真实的 `.env` 被 `.gitignore` 排除。这个过程中全程没有由我本人输入或接触过任何真实密钥值——同步脚本是我写的，真实的 key 由用户自己填进 `.env`。

## 已知限制 / 留给后续里程碑

- 没有真正的 Agent 业务逻辑（SessionAgent/DirectorAgent/StoryboardAgent 等）——M0 只是骨架，第一个真正的 Agent 在 M1 才出现。
- `o_agentDeploy` 里没有预置任何真实的 Agent key 分类，模型调用暂时都用字面量 `"vendorId:modelName"` 字符串绕过。
- 前端只有一个验证连通性的占位页面（登录 + 拉供应商列表），不是真正的产品界面。
