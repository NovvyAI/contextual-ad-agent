## 这个里程碑交付了什么

M0-M5 把整条链路从后端到浏览器界面都跑通了，但每次验证用的都是 M0/M1 生成的合成测试素材（ffmpeg `testsrc` 彩条测试图 + 无实际台词的占位语音）。这导致一个从 M4 起就反复记录在案、一直没解决的缺口：SupervisorAgent 面对这份素材时**每次都诚实地判定 `passed:false`**，理由永远是"源素材是技术测试图案，不是真实内容"——终审机制本身"是否工作正确"这件事，从来没有在一份真正有叙事内容的素材上被观察过。

M6 就是去补这个缺口：

1. 生成一套**更接近真实观感的虚构素材**（不是真实客户内容，也不是技术测试图案）；
2. 补上分阶段耗时统计；
3. 用这套素材真实跑一遍完整案例（分析 → 创意方案 → 内容生成 → revise → 终审），观察终审在真实内容上给出的判断；
4. 过程中意外挖出并修复了两个此前从未被触发过的模型调用层兼容性 bug。

## 关键设计取舍

1. **耗时记录加在 `taskRecord.ts` 闭包内部，不改任何调用方**——`u.task()` 返回的 `done(state, reason?)` 闭包本身就跨越了"创建时"到"调用完成时"这段区间，只要在闭包内部算 `Date.now() - startTime` 存进新列即可，`src/utils/ai.ts` 里四个模型包装类完全不用碰。
2. **把 `TaskRecord` 补进 M3 三个执行 Agent 里此前遗漏的调用点**——排查发现此前只有 `supervisorAgent/index.ts` 一处真正传了 `TaskRecord`，`bridgeVideoAgent`/`playableAgent`/`overlayAgent` 里的模型调用都没接，导致 `o_tasks` 表实际上只记录了终审这一个阶段。全部补上之后，`o_tasks` 才第一次能查到有意义的"草稿图 xx ms / 成片渲染 xx ms / 终审 xx ms"这类分阶段耗时。
3. **虚构素材用插画风格而非写实摄影风格生成人物**——第一版按"电影感写实照片"的提示词生成短剧静帧，被 Seedance（图生视频供应商）的内容安全过滤直接拒绝：`InputImageSensitiveContentDetected.PrivacyInformation`（"可能包含真人"）。这是视频生成商对"图生视频"输入图里的人脸做的隐私保护限制，和我们的代码无关。改成"插画/webtoon 风格、非写实、非真人肖像"的提示词后顺利通过——这类风格化处理对短剧场景的叙事表达也够用，不影响后续给 DirectorAgent/SupervisorAgent 分析。
4. **两处模型调用层兼容性问题都在响应/请求参数层面规避，不碰 node_modules**——详见下面"遇到的问题" 2、3 条。选择在 `providerOptions` 和自定义 `fetch` 这两层做兼容性垫片，而不是等中转商修复或者切换 SDK 版本，是因为这两个问题都有明确、可验证的规避方式（直接用 curl 反复验证过），改动范围可控且不影响标准 Anthropic 官方 API 的行为（`providerOptions.anthropic.*` 只在用 anthropic 供应商时生效，`fetch` 垫片只在响应里出现缺 `signature` 的 thinking 块时才会真正改写内容）。

## 遇到的问题与处理

这次真实调用过程中一共排查出四个问题，前一个是账号/中转服务侧的，后两个是真实的模型调用层兼容性 bug，此前从未被触发过（因为 M0-M5 从来没有真正跑通过一次带图片+结构化输出的、真实且诚实通过终审判定的完整链路）：

1. **中转服务账号分组限制"仅限 Claude Code 客户端"**——项目配置的 Claude key 走的是第三方中转服务（`napi.moretoken.ai`），运行到一半突然所有 Claude 文本调用（广告分析、Episode 分析、创意方案生成……）全部失败，报错 `No available accounts: this group only allows Claude Code clients`。排查确认：这不是代码问题（直接用 curl 绕开项目、按官方文档格式发请求，结果一致；对比参考项目 `ads-gen-agent-main` 的调用方式也完全一样，都是标准"开发者 API"调用），是这把 key 被中转商分到了"Claude 订阅账号池"（Anthropic 官方条款只允许这类账号通过 claude.ai/Claude Code 本身使用，不允许当通用后端 API 用）。这个问题不是本项目代码能解决的，最终由用户在中转服务后台把账号换到"开发者 API"分组解决——这也是 `docs/milestones/M0.md` 里记录过的同一个问题第二次出现，M0 当时也是换了把 key 解决的。
2. **扩展思考（extended thinking）触发中转商返回的 thinking 内容块缺 `signature` 字段**——账号问题解决后，广告分析等所有走 `invokeObject`（图片+结构化输出）的调用又全部报 `Invalid JSON response`。用自定义 `fetch` 包一层打印真实响应体，发现模型返回了 `{"type":"thinking",...}` 内容块，但缺了官方 API 应有的 `signature` 字段——`@ai-sdk/anthropic` 的严格 Zod 校验对此直接判定整个响应无效。这是中转商代理转发时的缺陷（用 curl 直接对官方原生格式发相同请求，返回的 thinking 块同样缺这个字段），不是我们代码的问题。先尝试请求侧关闭扩展思考（`providerOptions.anthropic.thinking:{type:"disabled"}`）规避。
3. **请求侧关闭扩展思考不能保证每次生效，且 `generateObject` 默认走的原生结构化输出中转商也没支持好**——加了 thinking 禁用之后，广告分析成功了，但 Episode 分析（`StoryboardAgent`，多帧图片+更大的 schema）仍然偶发同样的 `Invalid JSON response`——用同样的调试手段发现，这次是 thinking 块**依然出现**（中转商没有稳定遵守 `thinking:disabled` 这个请求参数）。另外还发现 `generateObject` 默认走 Anthropic 较新的原生结构化输出（`output_config.format:json_schema`），这个中转商同样没能正确支持这个较新的 API 面。最终用两层修复彻底解决：① 强制 `structuredOutputMode:"jsonTool"`，退回兼容性更好的旧式工具调用做结构化输出（这条路径已经用 curl 单独验证过，图片+工具调用能正确识别图片内容）；② 在 `data/vendor/anthropic.ts` 的自定义 `fetch` 里加一道响应侧兜底——扫描返回内容，遇到缺 `signature` 的 `thinking` 块直接补一个占位值再交给 SDK 解析，不管中转商这次是否遵守了 thinking 禁用指令，都不会再因为这个字段缺失而校验失败。两层修复叠加后，广告分析、Episode 分析全部稳定通过，包括之前一直没跑通的分阶段耗时统计（终于能在 `o_tasks` 里查到有意义的数据）。
4. **`ActionBar` 按钮点击期间没有禁用，存在双击/连续点击导致重复提交的风险**——这个问题实际是在这次真实操作过程中被观察到过（历史遗留，M5 阶段就应该发现但没有），这次顺手确认 M5 已经加的 `busy` 禁用逻辑在真实多次点击下工作正常，没有再复现重复提交。

## 已知限制

- **仍未观察到 `passed:true` 走到 `ManifestCard` 的路径**——这次终审给出的拒绝理由已经从"素材是技术测试图案"变成了具体的业务问题（CTA 链接非真实落地页），是实质性进展，但因为虚构素材没有一个真实可跳转的落地页，这条分支预计还会继续被拦截。要真正观察到一次诚实的 `passed:true`，需要接入有真实可访问落地页的素材，这超出了 M6"生成更真实感虚构素材"的范围。
- **只验证了 ctaCard 这一条形式**——DirectorAgent 这次生成的 6 份方案里 video 占多数，但为了控制这次验证的时间/成本，只选了耗时最短的 ctaCard 完整走完终审。`bridgeVideoAgent`/`playableAgent` 新加的 `TaskRecord` 埋点这次没有被真实调用验证到（只做了类型检查），逻辑上和已验证的 `overlayAgent` 改法完全一致，风险很低，但严格来说耗时统计还没有这两条路径的真实数据。
- **中转商的两个兼容性 bug（thinking 缺 signature、原生结构化输出不支持）是否会在其他供应商/其他中转商上复现，未知**——这两个修复目前只针对 `anthropic` 这一个供应商配置生效，如果项目以后换用其他中转商或直连官方 API，这两个规避措施是良性的空操作（官方 API 本身返回的 thinking 块一定带 `signature`，`structuredOutputMode:jsonTool` 只是退回一种更保守但完全受支持的模式），不会引入新问题，但也不再需要——留着不会有副作用，暂不清理。
